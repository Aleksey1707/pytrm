# Свод правил

- **Область.** `docs/rules/**` и `.claude/skills/**` — сам свод, его доставка и порядок ведения.
- **Читать перед.** Правкой любого файла свода, добавлением нового правила или файла; при
  выборе, какой файл свода открыть под задачу.
- **Словарь.** Плейсхолдеры и модальность — здесь, ниже.

## Как пользоваться

Правила обязательны к соблюдению. Файл открывается по триггеру из его пункта
**Читать перед** — до правки соответствующего слоя, а не после.

Всегда в контексте — только `20-agreements.md` (импорт в `AGENTS.md`) и карта свода оттуда же.
Остальные файлы подтягиваются по задаче: у каждого есть одноимённый skill, который велит
прочитать файл целиком. Skill выбирает модель — если правишь слой, а свод не подтянулся,
читай файл сам.

При расхождении источников приоритет такой:

| Приоритет | Источник | Что задаёт |
|---|---|---|
| 1 | `AGENTS.md` | язык, тон, формат ответа, команды сборки |
| 2 | файл свода | нормы слоя |
| 3 | код | как есть сейчас; расхождение с правилом — дефект кода, а не правила |

Приоритет 3 читается буквально: если код расходится со сводом, правится код. Осознанные
отступления живут в `DEBT.md` — сверься с ним, прежде чем «чинить» найденное несоответствие.

## Карта свода

| Файл | Skill | Тема | Читать перед |
|---|---|---|---|
| `10-architecture.md` | `architecture` | слои пакета, публичный API, граф импортов, `Registry`, DI и конфигурация | новым модулем, правкой `__init__.py`, `Registry`, `configurations.py`, `decorators.py` |
| `11-propagation.md` | `propagation` | семантика семи правил `Propagation`, инварианты `_initialize` и `_do`, `exclude` | правкой `bases.py`, добавлением правила распространения, разбором поведения вложенных блоков |
| `12-errors.md` | `errors` | иерархия `BaseTrmException`, `default_message`, контракт `:raises` | новым исключением, правкой иерархии, добавлением `:raises` в docstring |
| `13-impls.md` | `impls` | обёртка `Transaction`, менеджер и `create`, extras и опциональные импорты | новой реализацией БД, правкой существующей, добавлением extra в `pyproject.toml` |
| `19-testing.md` | `testing` | обвязка `tests/`, переиспользуемые наборы, маркер `integration`, `# given/when/then` | новым тестом, правкой `conftest.py`, добавлением набора для новой реализации |
| `20-agreements.md` | — (всегда) | CQS, `get` / `find`, иерархия классов, документация, аннотации, правило понижения, пайплайн `make` | любой правкой кода |
| `00-index.md` | — | карта свода, словари плейсхолдеров и модальности, стандарт оформления | правкой свода |
| `DEBT.md` | — | осознанные отступления от сводов: что не чинится сейчас и почему | «починкой» найденного несоответствия |

Номера идут с шагом, свободные номера зарезервированы под новые своды. Номер участвует
только в имени файла и порядке в карте; имя скилла его не содержит.

## Доставка: скиллы

Файл — источник истины, skill — только доставка. Правки вносятся в `docs/rules/*.md`;
`SKILL.md` трогать нужно, только если поменялось имя файла или область применения.

- имя скилла = имя файла без номера и расширения (`13-impls.md` → `impls`); иначе связь
  «свод ↔ skill» держится на памяти, а не на проверке;
- `description` скилла MUST перечислять содержимое свода и заканчиваться триггерами
  «Использовать при …» — по нему модель и решает, грузить ли файл;
- тело `SKILL.md` — указатель на файл и на `DEBT.md`, не пересказ правил: пересказ разойдётся
  с источником;
- у `20-agreements.md` скилла нет: он всегда в контексте импортом из `AGENTS.md`.

Проверяется: `make rules-check` — у каждого свода есть skill с ожидаемым именем, непустым
`description` и ссылкой на свой файл.

## Плейсхолдеры

Свод описывает конкретный код, поэтому имена модулей и классов пишутся как есть
(`pytrm.impls.sqlalchemy.SqlAlchemyTransactionManager`). Плейсхолдеры остаются только там,
где норма верна для любой реализации.

| Плейсхолдер | Значение |
|---|---|
| `<Impl>` | имя реализации в CamelCase (`SqlAlchemy`, `Redis`, `MongoMotor`) |
| `<impl>` | модуль реализации в `pytrm/impls/` (`sqlalchemy`, `redis`, `mongo/motor`) |
| `<extra>` | имя extra в `pyproject.toml` (`sqlalchemy`, `redis`, `mongo-motor`) |

## Модальность

Нормы записываются латиницей заглавными; всё остальное в тексте — пояснение, а не норма.

| Слово | Значение |
|---|---|
| MUST | обязательно; нарушение — дефект |
| MUST NOT | запрещено |
| SHOULD | по умолчанию так; отступление требует причины на call site |
| SHOULD NOT | так не делать без причины |
| MAY | допустимо, выбор за автором |

Расплывчатые формулировки («по возможности», «желательно») MUST NOT заменять модальность:
правило либо норма, либо пояснение.

## Шаблон файла правил

````markdown
# Реализации

- **Область.** `pytrm/impls/**`, extras в `pyproject.toml`.
- **Читать перед.** Новой реализацией БД; правкой существующей.
- **Словарь.** Плейсхолдеры и модальность — `00-index.md`.

## <Тематический блок>

Норма формулируется через MUST / MUST NOT / SHOULD / SHOULD NOT / MAY.

Проверяется: `uv run mypy`.

### <Подтема>

```python
# плохо — <причина>
...

# хорошо
...
```

## Связанные правила

- Соглашения по коду — `20-agreements.md`
- Тесты — `19-testing.md`
````

Оформление, общее для всех файлов свода:

- шапка — список из трёх пунктов (`- **Область.**`, `- **Читать перед.**`, `- **Словарь.**`);
  подряд идущие строки Markdown склеивает в один абзац, поэтому ключи MUST быть пунктами,
  а перенос уходит под отступ;
- заголовки: один H1, блоки — H2, подтемы — H3; H4 MUST NOT;
- у каждого fenced-блока MUST быть указан язык (`python`, `bash`, `markdown`, `text`);
- строка `Проверяется: …` ставится только там, где проверка существует (правило `ruff`,
  настройка `mypy`, тест, шаг `make`); отсутствие проверки не проговаривается;
- проза — не длиннее 100 символов в строке; таблицы и содержимое fenced-блоков — исключение;
- ссылка внутри свода — `` `13-impls.md` ``;
- последний H2 файла — `## Связанные правила`.

Проверяется: `make rules-check` (`scripts/rules_lint.py`).

## Как добавлять правило

- Правило живёт в **одном** файле; в остальных — строка-ссылка. Дублирование текста
  MUST NOT: копии расходятся при правке одной из них.
- Дом правила выбирается по слою, к которому оно относится, а не по тому, откуда
  вспомнилось: тест — `19-testing.md`, стиль и именование — `20-agreements.md`,
  распространение транзакции — `11-propagation.md`, обёртка над БД — `13-impls.md`.
- Новое правило MUST приносить с собой либо пример «плохо / хорошо», либо строку
  `Проверяется: …` — иначе оно нечитаемо в разборе конкретной правки.
- Новый файл свода: имя `NN-<тема>.md`, шапка и хвост по шаблону, строка в карте выше **и**
  в карте `AGENTS.md`, скилл `.claude/skills/<тема>/SKILL.md`.
- Отступление, которое не чинится, — строка в `DEBT.md` с причиной и условием выхода,
  а не молчаливое расхождение кода со сводом.

## Связанные правила

- Архитектура пакета — `10-architecture.md`
- Соглашения по коду — `20-agreements.md`
